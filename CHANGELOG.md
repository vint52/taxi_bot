# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [2.1.0] - 2026-09-10

### Добавлено
- Тесты (pytest): конфигурация, парсинг HTML кабинета, форматирование, хранилище, планировщик и маршрутизация обновлений через реальный диспетчер aiogram. Redis подменяется `fakeredis`, сеть не нужна.
- Переменная `LOG_LEVEL` для управления уровнем логирования (по умолчанию `INFO`).
- Переменная `BOT_TIMEZONE` для времени последнего обновления в сообщении администратора (по умолчанию `Europe/Moscow`).
- Общий обработчик ошибок: при сбое в обработчике пользователь получает короткое сообщение вместо тишины.
- `requirements-dev.txt` и `pyproject.toml` с настройками ruff и pytest.

### Изменено
- Python 3.11 → 3.13, aiogram 3.22 → 3.31, requests 2.31 → 2.34, lxml 4.9 → 6.1, redis 7.0 → 8.1, образ Redis 7 → 8.
- Работа с Redis переведена на `redis.asyncio`; опрос кабинета такси выполняется в отдельном потоке и больше не блокирует цикл событий бота.
- Клиент кабинета логинится при первом запросе и сам переавторизуется при истёкшей сессии. Бот больше не падает на старте, если кабинет недоступен.
- Обработчики собраны в два роутера aiogram (пользовательский и административный) с фильтром администратора и типизированными callback-данными. Классы-делегаты удалены.
- Дублирующийся код сводки по логам, рассылки, клавиатур и проверки прав сведён в одно место.
- Сообщения бота нигде не превышают лимит Telegram: длинные логи обрезаются.
- Администратор освобождён от ввода кодового слова в приватном режиме и регистрируется сразу.
- Уровень логирования по умолчанию `INFO` вместо зашитого `DEBUG`.
- Пароль Redis передаётся серверу из `RDS_PASSWORD` через docker-compose, а не хранится в `redis/conf/master.conf`.
- Бот стартует только после успешного healthcheck Redis; дублирующий блок `environment` в docker-compose удалён.
- Dockerfile больше не ставит gcc и libxml2-dev: lxml устанавливается из готовых колёс.
- flake8, isort и autopep8 заменены на ruff.
- `pytz` заменён на стандартный `zoneinfo`.

### Исправлено
- Сводка активности пользователя (`/logs <id>` и кнопка «Логи» у пользователя) считала маркеры, которых в логах никогда не было, и всегда показывала нули.
- После удаления пользователя через inline-кнопку callback отвечался дважды.
- Кнопка «Пользователи» при пустом списке показывала отладочную информацию вместо обычного сообщения.
- Нетекстовые сообщения (стикеры, фото) обрабатываются как неизвестная команда, а не падают в обработчике.

### Удалено
- `src/utils.py`, `src/__init__.py`, классы `BotHandlers`, `UserHandlers`, `AdminHandlers`, `CallbackHandlers`.
- Неиспользуемые константы и дублирующиеся тексты сообщений.

### Обратная совместимость
- Формат данных в Redis не менялся, существующие баланс, поездки и пользователи подхватываются.
- Inline-кнопки в сообщениях, отправленных предыдущей версией, перестают работать и предлагают открыть список пользователей заново.
- Убедитесь, что `RDS_PASSWORD` в `.env` совпадает с паролем, который раньше был задан в `redis/conf/master.conf`.
